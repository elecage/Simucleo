# 외부 부품 계획

부품은 **신호를 주고받는 방식**에 따라 시뮬레이션 난이도와 필요한 MCU Peripheral이 달라진다.
아래 단계(Tier)는 이 의존성을 기준으로 정한 구현 순서다.

| 상호작용 방식 | 모델링 수준 | 예 |
|---|---|---|
| 디지털 레벨 | 핀 High/Low 이벤트 | LED, 버튼, 능동 부저 |
| PWM/주파수 | 프레임당 듀티비·주파수 적분 | LED 밝기, 수동 부저, 서보, 모터 |
| 아날로그 | DC 회로 해석(MNA) → ADC | 가변저항, LDR, 아날로그 온도센서 |
| 버스 트랜잭션 | I2C/SPI/UART Peripheral과 **트랜잭션 단위**로 연결 | RTC, OLED, SD 카드, 가상 콘솔 |
| 타이밍 민감 단선(single-wire) | 핀 엣지 타임스탬프로 펄스 폭 해석 | NeoPixel, DHT11/22 |

## Tier 1: 디지털 기본 (M2–M3) ✅

구현됨: Nucleo, 브레드보드, 점퍼선, 저항(색띠), LED(색 선택), RGB LED(공통 캐소드/애노드), 택트 스위치,
능동·수동 부저, ST-LINK 가상 콘솔. 전기 모델은 DC 노드 해석이고([아키텍처](architecture.md) 4절),
저항 없는 LED는 빨간 점멸 표시와 경고로 알린다. 부저 소리는 Web Audio 발진기로 낸다(수동 부저는 신호 주파수).
아직 없는 것: 스위치 바운스, 플로팅 입력 경고, USB-UART 모듈 부품.

| 부품 | 핀 | 전기 모델 | 표시/상호작용 | 교육용 검사 |
|---|---|---|---|---|
| **Nucleo-F401RE** | **Arduino 헤더(CN5/6/8/9) + Morpho 헤더(CN7/CN10, 2×19)** | 핀 = GPIO 모델. 같은 신호 핀(예: D13 = CN10-11 = PA5)은 내부 버스로 연결 | 내장 LD2(PA5), B1(PC13) 클릭, RESET | 핀 이름 `CN10-11 · PA5 · LD2 · SCK` 표시, ST-LINK가 쓰는 핀(PA2/3, PA13/14, PH0) 경고 |
| **브레드보드 (하프/풀)** | 행 5홀 버스, 전원 레일 | 부품 내부 버스 | 리드를 꽂으면 자동 연결 | — |
| **점퍼선** | 2 | 이상적인 도선 | 색상, 곡선 | — |
| **저항** | 2 | 선형 저항 | 색띠 자동 표시 | — |
| **LED 5mm** (색상 선택) | A, K | Vf + 전류 제한 | 밝기(PWM 듀티 적분), 글로우 | 저항 없음 → **소손 애니메이션** |
| **RGB LED** (공통 캐소드/애노드) | 4 | LED × 3 | 색 혼합 | 공통 단자 극성 오류 |
| **택트 스위치** | 4 (2쌍 내부 연결) | 접점, (옵션) 바운스 | 클릭/누르고 있기 | 풀업/풀다운 없음 → 플로팅 경고 |
| **능동 부저** | +, − | 켜짐/꺼짐 | 고정음 재생 | — |
| **수동 부저** | +, − | 엣지 주파수 | **AudioWorklet**로 실제 음 재생 | GPIO 직접 구동 전류 경고 |
| **가상 콘솔 (UART)** | TX, RX, GND | USART와 바이트 단위 연결 | 터미널 패널, 송신 입력, 줄바꿈 모드 | **보레이트 불일치 → 깨진 글자** 재현 |

가상 콘솔은 두 형태로 제공한다.
- **ST-LINK VCP**: 보드에 내장된 USART2(PA2/PA3)로, 배선 없이 항상 연결된다.
- **USB-UART 모듈 부품**: 브레드보드에 꽂아 USART1/USART6 같은 다른 UART에 연결한다.

Morpho 헤더가 필요한 이유: Arduino 헤더에 없는 PC0–PC12, PB12–PB15, PB1/PB2/PB7, PA11/PA12, PD2 등을
써야 하는 경우가 많다(예: SPI2, I2C2/3, USART6, 추가 타이머 채널, 외부 인터럽트 핀). 핀 정의는 UM1724
기준이며, F401RE LQFP64에는 PB11이 없으므로 CN10-18은 NC로 둔다.

## Tier 2: 아날로그 · 구동 (M5) ✅

모두 구현됨. 회로 해석([아키텍처](architecture.md) 4절)에 저항(가변저항, LDR), 전원 조건이 있는 전압원(온도센서), 고임피던스 입력(서보 신호, 모터 드라이버 입력)으로 들어간다.
DC 모터는 H-브리지 드라이버 모듈(L9110S 계열)이 달린 형태로 제공한다.

| 부품 | 모델 | 표시/상호작용 |
|---|---|---|
| **가변저항** (10kΩ 등) | 3단자 분압기 → MNA | **노브를 잡고 돌리기**(270°)·휠, 슬라이더 |
| **조도센서 (LDR)** | 조도에 따른 저항 | **손전등을 끌어 거리 조절**(거리의 제곱에 반비례), ✋ 누르는 동안 손으로 가리기, 슬라이더 |
| **아날로그 온도센서** (TMP36/LM35 계열) | 출력 V = f(T) | **손가락으로 누르면 데워짐**(체온 33 °C, 시간 상수 3 s, 떼면 식음), 슬라이더 |
| **서보 (마이크로 서보 계열)** | 펄스 폭 1–2 ms → 목표 각, 각속도 제한 | 혼(horn) 회전, 0–180° 눈금과 부채꼴 |
| **DC 모터 + H-브리지 모듈** | IN1/IN2/EN(PWM) → 1차 ODE | 회전 애니메이션(표시 살), 방향 화살표, RPM |

## Tier 3: I2C/SPI 버스 장치 (M6) ✅

| 부품 | 버스 | 구현 범위 | 표시/상호작용 |
|---|---|---|---|
| **SSD1306 0.96" OLED 128×64** | **I2C**(0x3C/0x3D) / **SPI 4선**(D/C, RES, CS) | 명령 셋(주소 모드, 페이지/컬럼, 대비, 반전, on/off, 차지펌프) ✅, 스크롤은 이후 | 프레임버퍼를 화면으로 렌더링 ✅ |
| **I2C RTC** (DS3231 호환) | I2C 0x68 | 시간/날짜 레지스터(BCD) ✅, 제어/상태 ✅(저장만), 온도 레지스터 ✅, 알람은 이후 | 시작 시 PC 현지 시간으로 초기화 ✅, 배터리 백업 ✅ |
| **SD 카드 (SPI 모드)** | SPI + CS | CMD0/8/55/41/58/9/10/12/13/16/17/18/24/25 ✅, CMD0·CMD8 CRC 검사 ✅ | **디스크 이미지 업로드/다운로드** ✅, 빈 카드는 펌웨어가 `f_mkfs`로 포맷, **내용 자동 저장**(IndexedDB, 프로젝트·부품별, 쓰인 블록만) ✅, 카드 비우기 ✅ |
| **I2C 온습도센서** (AHT20/SHT3x 계열) | I2C | AHT20: 측정 명령 → 80 ms → 데이터, CRC ✅ | 온도/습도 슬라이더 ✅, 누르면 손가락·입김으로 온도·습도가 오름 ✅ |

**설계 원칙**: MCU의 I2C/SPI Peripheral이 버스를 구동하면, 장치 모델은 **트랜잭션 단위**
(`start/addr/write/read/stop`, `transfer(byte)`)로 연결해 빠르게 동작시킨다.
비트뱅잉(GPIO로 버스를 직접 구현한 경우)은 핀 레벨 디코더 어댑터를 거쳐 같은 장치 모델에 연결한다.
SSD1306 같은 장치는 I2C와 SPI 양쪽 프런트엔드가 **하나의 장치 코어를 공유**한다.

## Tier 4: 타이밍 민감 단선 장치 (M7) ✅

| 부품 | 프로토콜 | 필요한 MCU 기능 | 비고 |
|---|---|---|---|
| **NeoPixel** (WS2812B 호환): 단일, 스트립, 링, 매트릭스 | 800 kHz NRZ, 0/1을 펄스 폭으로 구분, 50 µs 이상 Low면 리셋(latch) | 보통 **TIM PWM + DMA** 또는 SPI MOSI 트릭 | 핀 엣지 타임스탬프로 비트 디코드 ✅, 타이밍 허용 오차 위반 시 경고 ✅. 스트립 8, 링 12/16/24, 매트릭스 8×8 ✅, 체인 연결은 이후 |
| **DHT11 / DHT22** | MCU 시작 신호 → 센서 응답 → 40비트 펄스 폭 | µs 지연(TIM 또는 DWT CYCCNT), 입력 핀 폴링/입력 캡처 | 양방향 오픈드레인 단선 ✅, 시작 신호 길이 검사 ✅, 누르면 손가락·입김으로 온도·습도가 오름 ✅ |

이 장치들은 **사이클 근사 타이밍**과 **DMA**에 의존하므로, CPU 사이클 모델과 DMA가
안정된 뒤에 구현한다. 펌웨어의 타이밍이 허용 오차를 벗어나면 "실제 하드웨어에서도 실패할 수 있음"을
알려 주는 것이 교육적 가치다.

## Tier 5: 추가 부품 (M8) ✅

7세그먼트(단일/4자리 멀티플렉싱), I2C 문자 LCD(PCF8574 + HD44780), 스테퍼(28BYJ-48 + ULN2003),
초음파 거리센서(HC-SR04P), 1-Wire 디지털 온도센서(DS18B20), 로터리 엔코더(KY-040), 4×4 키패드, NTC 서미스터.
초음파 센서는 앞의 장애물을 끌어 거리를 바꾸고, 서미스터와 DS18B20은 손가락으로 눌러 데운다(M14).

## 직접 조작 (M14)

입력 부품은 속성 창 슬라이더 말고도 브레드보드에서 실제 물건처럼 조작할 수 있다. 부품 그림의 조작 부분에
`data-drag="이름"`을 달고 부품 정의의 `controls`에 같은 이름으로 조작을 등록하면, 편집기가 그 부분을 끄는 동작을
조작으로, 나머지 몸체를 끄는 동작을 이동으로 나눈다. 조작은 슬라이더와 같은 속성에 쓴다.

| 조작 (`web/src/parts/controls.ts`) | 쓰는 부품 | 동작 |
|---|---|---|
| `rotaryKnob` | 가변저항 | 중심 둘레로 돌린 각도만큼(270° = 전체), 휠 한 칸 2 % |
| `slideHandle` | LDR 손전등, 초음파 장애물 | 손잡이와 센서 사이 거리 ↔ 값(LDR: 제곱 반비례, 초음파: 제곱 눈금) |
| `holdValues` | LDR ✋ | 누르는 동안 정한 값(5 lux), 떼면 원래 값 |
| `fingerTouch` | TMP36/LM35, 서미스터, DS18B20, DHT, AHT20 | 누르는 동안 33 °C(습도 85 %)를 향해 1차 지연, 떼면 원래 값으로. 끌면 이동 |
| `tiltControl` | MPU-6050 | 끄는 방향으로 roll·pitch, 끄는 속도가 자이로, 빠르게 왔다 갔다 하면 흔들기 |
| `shakeControl` | MPU-6050 | **흔들기** 버튼: 약 0.45 s 동안 잦아드는 가속도 `ax`·`ay`·`az`(g)를 중력에 더함 |

## Tier 6: 동작 센서 · 도트 매트릭스 · 적외선 (M13) ✅

| 부품 | 프로토콜 | 필요한 MCU 기능 | 비고 |
|---|---|---|---|
| **MPU-6050** (GY-521, 가속도·자이로) | I2C 0x68 (AD0 High면 0x69), 레지스터 포인터 쓰기 → 자동 증가 연속 읽기 | I2C (`HAL_I2C_Mem_Read`) | 전원을 켜면 잠자기(PWR_MGMT_1 = 0x40, 측정값 0), DEVICE_RESET, SMPLRT_DIV·CONFIG 저장, GYRO_CONFIG ±250–2000 °/s, ACCEL_CONFIG ±2–16 g, 0x3B–0x48 빅엔디언 int16(온도 = 값/340 + 36.53). 입력: roll·pitch(중력 방향), 자이로 X/Y/Z, 흔들림 가속도 `ax`·`ay`·`az`(g, 중력에 더함), 온도. **부품을 마우스로 끌어 기울이고**, 끄는 속도가 자이로 값이 됨. **흔들기** 버튼이나 빠른 왕복 끌기로 흔듦 |
| **MAX7219** 8×8 LED 매트릭스 (FC-16, 1–4개 체인) | 16비트 프레임(주소, 데이터) MSB부터, CS Low 동안 CLK 상승 에지, CS 상승 에지에 반영 | **하드웨어 SPI**(SCK·MOSI) 또는 GPIO **비트뱅잉** 둘 다 | N개면 마지막 16×N비트가 남고 먼저 보낸 프레임이 가장 먼 모듈로. **DOUT 체인**: 밀려난 비트가 16×N클럭 뒤 DOUT으로 나오므로(CLK 하강 에지에서 바뀜) 따로 놓은 부품의 DIN을 DOUT에 잇고 CLK·CS를 같이 연결해도 이어진다 — 비트뱅잉은 넷으로, 하드웨어 SPI는 넘친 바이트를 다음 부품에 넘겨서. `count`와 섞어 써도 됨. 줄 레지스터 0x1–0x8, 디코드(Code-B), 밝기, 스캔 한도, 셧다운(처음엔 꺼짐), 디스플레이 테스트. 밝기만큼 흐리게 그림 |
| **IR 수신기 + 리모컨** (VS1838B, NEC) | 복조된 NEC 프레임: 9 ms Low, 4.5 ms High, 32비트 LSB부터(주소, ~주소, 명령, ~명령), 누르고 있으면 108 ms마다 반복 코드 | 입력 캡처(하강 에지 간격) 또는 EXTI + 타이머 | 출력은 Low 활성(10 kΩ 풀업). 17키 리모컨을 클릭: 주소 0x00, 1=0x45 2=0x46 3=0x47 4=0x44 5=0x40 6=0x43 7=0x07 8=0x15 9=0x09 *=0x16 0=0x19 #=0x0D ▲=0x18 ◀=0x08 OK=0x1C ▶=0x5A ▼=0x52 |

## 후속 후보

여러 1-Wire 장치(SEARCH ROM), 블루투스/USB-UART 모듈, MPU-6050 FIFO·인터럽트, NeoPixel 부품끼리 DOUT → DIN 체인.

## 부품 정의 포맷

부품은 **모양 + 핀 + 내부 버스 + 전기 모델 id + 속성 + 시각 바인딩**으로 정의한다
(현재 `web/src/parts/*.tsx`). 핀 좌표는 0.1인치(2.54 mm) 그리드 배수이고,
서로 다른 부품의 핀이 같은 그리드 점에 있으면 연결된 것으로 본다(브레드보드에 꽂는 동작).

그래픽은 프로젝트에서 직접 제작한다. 외부 부품 라이브러리(Fritzing 등)는 라이선스(CC-BY-SA)가
MIT와 맞지 않으므로 그대로 가져오지 않는다. 제조사 로고와 상표도 넣지 않는다.
